# 多焦点自动采集、标定与定位

入口 `calibration/autofocus_calibration.py`，无需为每个对焦数值手动拍几十张。先选实际工作范围内的近、中、远三个焦点，再每次摆一个棋盘姿态，按一次 S 自动轮换各档拍摄。建议 15–20 个姿态；15 个完整姿态默认每档得到 12 张训练图及 3 张独立验证图。失焦/遮挡/晃动时该档会跳过，需补充姿态至每档至少 10 张有效训练图。

## 1. 启动与选焦点

先关闭其他占用相机的程序，在项目根目录运行：

```powershell
python -m calibration.autofocus_calibration capture --camera 1 --backend dshow --square-mm 20
```

这里编号 1 是之前成功读写焦点的相机；`--square-mm` 按实物打印格子边长填写。始终使用同一设备、分辨率、图像方向与图像采集模式。采集、标定与定位沿用配置中的 640×480 和 180° 旋转。

窗口先进入选择阶段：

1. 将棋盘放在实际工作范围的近端，按 **A** 自动对焦，等待清晰且读数稳定后按 **1**，记录近端焦点。
2. 放在工作范围中间，再按 A，稳定后按 **2**。
3. 放在远端，再按 A，稳定后按 **3**。
4. 按 **Enter** 确认。至少需要两个不同读数，推荐三个；近远标签对应的数值大小不一定相同方向，程序会按驱动数值排序。

这是驱动回读，不是独立编码器。程序不会把 259 等此前测试值当作推荐值。若近/中/远读数没有变化，检查图像、自动对焦状态或工作距离后再记录，不强行生成不同数字。

已知经过核实的焦点时，也可直接传入：

```powershell
# 数值仅演示格式，请替换为自己的实际焦点
python -m calibration.autofocus_calibration capture --camera 1 --focus-values 200,260,320 --square-mm 20
```

## 2. 每个姿态自动切焦采集

- 摆好棋盘，保持整板完整入镜；按 **S/空格**，在这一轮自动切焦期间持稳。程序关闭自动对焦后逐档请求镜头位置，读帧等待稳定，核验实际回读，并要求角点连续稳定、清晰度达到参考阈值后保存。
- 一轮结束后再移动棋盘。采集不同左右/上下倾角、画面中心/四周位置，以及清晰范围内不同距离；不连续保存同一个姿态。
- 每第 5 个姿态完整留作验证，不进入训练。这一轮还自动拍摄相邻档位的中间焦点，用来测试插值，故等待时间会更长。
- 不同焦点的清晰距离不同，同一姿态未必能全部清晰。超时会显示跳过，按提示到适当距离补拍，不能靠降低阈值强行接受模糊图。
- 默认切焦后等 1.5 秒，最多额外等 2.5 秒查找稳定棋盘。可用 `--settle`、`--timeout` 调整。其间窗口保持刷新，Q 随时退出。
- 切换自动到手动时，先读帧等待手动模式稳定，再写入焦点；已是手动时不重复关闭自动对焦。焦点写入允许最多三次重试，只有回读在目标值持续稳定后才进入拍摄；失败时跳过该档，绝不按请求值给错误焦点图像标注。`events.json` 保存每次请求、回读、重试及成功/失败，可用于排查驱动的异步控制。
- 按 **F** 结束采集并自动批量标定；**Q** 仅保存退出。每档训练图不足 10 张会拒绝拟合并指出具体焦点。采集画面显示逐档训练数量，可继续补拍后再 F。

输出在 `calibration/focus_maps/session_时间/`。`session.json` 记录姿态和划分，`train/`、`validation/` 按焦点独立保存完整、未标注 PNG，子目录 `capture.json` 记录每张的焦点及手动模式。Q 退出后也可离线标定：

```powershell
python -m calibration.autofocus_calibration fit --session "calibration/focus_maps/实际会话目录"
```

重新拟合同一输出需加 `--overwrite`。原始图片不删除。

## 3. 标定与验证输出

`calibrated/` 内含逐档内参 JSON、逐张重投影误差、角点叠图、去畸变对比，以及 `focus_map.json` 和 `标定报告.md`。

每档独立使用训练图拟合五系数针孔模型。验证图只拟合棋盘外参，不用于训练内参；相邻参数线性插值后的中间焦点也用未参加训练的姿态检查。默认端点和中点各至少 3 张验证图、每张 RMSE 不超过 1 px，才在表里登记该区间通过。阈值可通过 `--max-validation-rms` 调整，但提高阈值不是改善精度。

验证结果反映独立棋盘图的重投影误差。参数表记录各档和区间的验证结果，供后续定位精度评估使用。

## 4. 保持自动对焦的定位

定位程序默认使用 `config/positioning_config.json` 中 `focus_map_file` 指定的焦点表。要切换到新标定的焦点表，可以按标定报告中的命令运行。

```powershell
python positioning.py --camera 1 --camera-backend dshow --focus-map "实际会话目录/calibrated/focus_map.json" --csv positioning_dynamic_focus.csv
```

动态模式会请求开启自动对焦，在读帧前后读取焦点，连续三帧一致后计算内参，再运行加权 PnP。焦点正好命中标定档位时直接取该档参数。档位之间线性插值，标定范围外用同侧最近两档线性外推。各档及区间的验证结果作为标定记录。焦点变化期间显示 FOCUSING。需要使用固定内参时，可通过 `--config` 指定一份将 `focus_map_file` 设为 `null` 的配置，由 `calibration_file` 指定内参文件。

普通 UVC 驱动回读不能保证与曝光帧严格同步，连续稳定检查只能降低错配风险。若对焦长期变化或回读失效，则动态定位不可用；需要设备 SDK 的逐帧元数据或工作阶段稳定对焦。这部分必须实机核验，不能由合成测试代替。

保存定位快照时，CSV 记录该帧的 `camera_fx_px`、`camera_fy_px` 和 `focus_position`。同名 JSON 另存完整 K/D、检测器中心、标签权重和参数表路径。CSV 写入失败时，PNG 和 JSON 一起回滚。

## 验证范围

测试覆盖表插值、外推、相机读数稳定性、分焦点保存、批量 OpenCV 合成标定及独立中间焦点验证、定位流程传递焦点、快照元数据保存与回滚。实际镜头动作、焦点回位、景深和曝光同步需通过实机检验。
